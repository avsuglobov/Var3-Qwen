# AI Workspace — прототип личного кабинета ИИ-сотрудников

> **[ПРОМТ ПРОДОЛЖЕНИЯ — не удалять]** Полный промт для нового чата (этапы 16–20, прод-контур) хранится в корне репозитория: [continuation-prompt.md](../continuation-prompt.md). Версия от 2026-11-27.

> **Важно о формате.** Среда выполнения не запускает Next.js / сборку фулстек-проекта,
> поэтому требование «Next.js 15 + App Router» реализовано как **статический прототип
> без сборки**: откройте `index.html` напрямую в браузере. Весь дизайн-язык, обе темы,
> лейаут, все 13 разделов и интерактив сохранены. Соответствие запрошенному стеку
> описано ниже в разделе «Маппинг на Next.js-стек» — это готовый каркас для переноса.

## Запуск

```bash
# любой способ открыть статику; например:
python3 -m http.server -d /home/z/my-project/download 8080
# затем http://localhost:8080
```

Или просто открыть `download/index.html` в браузере. Тема по умолчанию — системная,
переключатель в верхней панели (Светлая / Тёмная / Системная). Горячие клавиши: **⌘K / Ctrl+K**
— командная палитра, **1–4** — основные разделы.

## Дизайн-система (одна архитектура, два языка)

Только `styles.css` хранит hex-значения — в `:root` (светлая) и `.dark` (тёмная).
Компоненты используют только токены (`var(--primary)` и т.п.); хардкод цветов в компонентах
запрещён и проверен (`grep` по `violet|purple|slate-|gray-|bg-white|#fff` — пусто).

| Токен            | Светлая «Тёплая редакция» | Тёмная «Fincher Monitor» |
| ---------------- | ------------------------- | ------------------------ |
| canvas/background| `#FAF7F2`                  | `#0B0D0E`                |
| surface/card     | `#FFFFFF`                 | `#14171A`                |
| elevated/muted   | `#F3EEE5`                 | `#1E2226`                |
| border           | `#E7E1D6`                 | `#262B30` (1px)          |
| foreground       | `#1A1A17`                 | `#D8DEE4`                |
| muted-foreground | `#6B675F`                 | `#7A858E`                |
| primary/accent   | `#B8431A` (терракота)     | `#C88A36` (янтарь)       |
| critical         | `#B3261E`                 | `#B8332A`                |
| status           | `#1F5C4A`                 | `#3A6B5C`                |
| шрифт заголовков | Fraunces                  | Inter                    |
| шрифт интерфейса | Geist                     | Inter                    |
| шрифт данных     | Geist Mono                | JetBrains Mono (tabular) |
| метки секций     | sentence case, Geist      | UPPERCASE, моно, .08em   |
| радиус карточки  | 12px                      | 4px                      |
| радиус кнопок    | 8px                       | 2px                      |
| тень подъёма     | `0 8px 24px rgba(26,26,23,.12)` | `0 4px 12px rgba(0,0,0,.7)` |

Тёмные эксклюзивы: радиальный «свет лампы» над рабочей областью, плёночное зерно
(inline-SVG `feTurbulence`, opacity .025, монохром, только в `.dark`, отключается при
`prefers-reduced-motion`), глубина через 1px-границы вместо мягких теней, без пилюль
(радиус 2px), без glassmorphism и bounce.

Общее: акцент сдержанно (одна главная кнопка на экран, активный пункт навигации, фокус-кольцо,
линии графиков); critical — только критичное; status — только «в сети/ОК». Статус всегда
дублируется текстом/иконкой («КРИТИЧНО», «В СЕТИ»). Контраст AA, видимый фокус
(`outline: 2px solid var(--ring)`), управление с клавиатуры, `aria-label` на иконочных кнопках.

## Список плейсхолдеров и демо-данных

Все данные помечены бейджем **«Демо»**. Цены, метрики, отзывы и названия клиентов
не выдумывались — там, где значения ещё не известны, стоит `—` с подсказкой.

- **Обзор**: KPI (лиды/счёта/сообщения ИИ/передачи менеджеру) — демо-счётчики; один KPI
  намеренно пустой (`—`), чтобы показать empty-state. График активности — демо-значения.
- **ИИ-сотрудники**: 5 агентов (Продажи, Поддержка, Снабжение, HR, РОП) с ролями, каналами,
  воронками, правилами согласования; мастер создания и тест-чат — демо-сценарии.
- **Диалоги**: 3 диалога (Демо-клиент А/Б/В…) с режимами «ИИ отвечает / ИИ в режиме чтения /
  Передача менеджеру». Ответы ИИ эмулируются задержкой («печатает…»).
- **CRM**: 6 демо-лидов в 3 воронках; журнал+инспектор (вид по умолчанию), канбан с DnD
  (4 стадии), таблица. Бейдж синхронизации с amoCRM — демо.
- **Лиды и автокасания**: импорт .xlsx (dropzone → превью → сопоставление колонок) —
  демо-превью; сценарий реактивации «Контакты → Автокасания → Передача менеджеру».
- **Документы**: шаблоны счёт/КП/акт, очередь согласования (одобрить/отклонить), правила
  «сам/согласует», отправка PDF (демо-тост). Суммы не показываются.
- **Хранилище**: описание компании (плейсхолдеры), 5 источников (PDF/DOCX/XLSX/WEB/API),
  переключатель «искать в интернете».
- **Команда**: конструктор цепочек, 2 шаблона (Услуги, Производство).
- **Снабжение**: запросы поставщикам, сводная таблица условий (без цен), передача результата.
- **Обучение**: 3 демо-курса с прогрессом, именной PDF-сертификат.
- **Аналитика (РОП)**: разбор диалогов менеджеров, нарушения скрипта, оценка качества (`—`),
  чат «вопрос руководителю».
- **Интеграции**: 8 карточек (amoCRM, Bitrix24, Telegram, WhatsApp, Календари, REST API,
  Документы, Телефония); бейдж статуса — прямоугольный, точка 8px (заливка/контур) + текст;
  главная кнопка экрана — «Запросить интеграцию».
- **Настройки**: профиль/компания/роли/каналы/уведомления/тариф. **Помощь**: поддержка + чат обучения.
- Иконки каналов и интеграций — монохромные (lucide), брендовых цветов и логотипов нет.

## Что подключить к реальному бэкенду

1. **Слой данных** (`data.js` → `lib/api/*.ts`): заменить фикстуры на REST-вызовы через
   интерфейсы `Agent`, `Channel`, `Lead`, `Deal`, `Stage`, `Funnel`, `Conversation`,
   `Message`, `Document`, `Template`, `ApprovalRule`, `KnowledgeSource`, `Integration`,
   `Course`, `Certificate`. Состояния: empty реализованы; loading/error-состояний нет (ограничение прототипа).
2. **ИИ-ответы**: эмуляцию «печатает…»/задержки заменить на стриминг от LLM (SSE/WebSocket),
   с правилами согласования как guardrail'ами перед отправкой.
3. **Интеграции**: мок-бейджи статуса → реальные OAuth/токены (amoCRM, Bitrix24, Telegram,
   WhatsApp, телефония) и webhook'и каналов; «Запросить интеграцию» → тикет в support.
4. **Документы**: генерация PDF по шаблонам на сервере (счёт/КП/акт), очередь согласования
   с ролями и лимитами.
5. **Аналитика (РОП)**: демо-оценки → реальный разбор диалогов моделью по скриптам,
   метрики качества цепочки.
6. **Аутентификация и тариф**: профиль/аватар/тариф — за реальным бэкендом (SSO/приглашения,
   биллинг). Пробный период «14 дн.» — счётчик на бэке.

## Три идеи улучшения

1. **Живой inbox с optimistic-обновлениями**: перевести «Диалоги» на TanStack Query +
   WebSocket, рисовать «печатает…» по реальным presence-событиям, а передачу менеджеру
   делать optimistic-мутацией с откатом. Сейчас это статичные фикстуры.
2. **Конструктор цепочек как граф**: сделать «Команду» настоящим canvas-редактором
   (dnd-kit + реактивные ноды, ветвления, условия), с превью прохождения заявки по цепочке
   и подсветкой узких мест (где ИИ чаще эскалирует к человеку).
3. **Единая «карта клиента»**: объединить контекст из «Диалоги», карточку лида в CRM,
   документы и историю обучения в один `CustomerContext`-провайдер — чтобы ИИ-сотрудник
   любой роли видел сквозную историю, а РОП мог оценивать не отдельный диалог, а путь клиента.

## v2: «живой» прототип (persist + CRUD)

Поверх статического каркаса добавлен слой `db.js` — данные стали изменяемыми и
персистентными. Всё хранится локально в браузере (`localStorage`, ключ `aiws-db-v2`),
никуда не отправляется. При любой мутации состояние автоматически перерисовывается.

- **Persist**: лиды, диалоги (сообщения), документы и онбординг сохраняются в `localStorage`
  и восстанавливаются после перезагрузки страницы. Тема и свёрнутость сайдбара персистились и раньше.
- **CRUD лидов**: кнопка «Создать лид» в CRM открывает модалку (имя, канал, воронка, агент,
  заметка); новый лид попадает в канбан/журнал/таблицу. Перетаскивание карточки между колонками
  меняет стадию и пишет событие в ленту (через `db.moveLeadStage`). В инспекторе — «Удалить».
- **CRUD документов**: «Создать документ» (тип, клиент, согласующий) → очередь согласования;
  «Одобрить/Отклонить» меняет статус; в каждой строке — удаление.
- **Онбординг кликом**: шаги в обзоре кликабельны — отметка «Готово/В процессе» переключается
  и сохраняется, прогресс-бар пересчитывается.
- **Диалоги**: ответ менеджера сохраняется в переписку и переживает перезагрузку.
- **Скриптованный тест-чат** (вкладка «Тест» у ИИ-сотрудника, а также ИИ-РОП и Помощь):
  ответы подбираются по ключевым словам («тариф», «возврат», «поставщик» …). **Честная метка:
  это демо-сценарий, не LLM** — модель не вызывается.
- **Экспорт/импорт/сброс**: Настройки → «Данные» — выгрузка базы в JSON, импорт из файла,
  сброс к исходным демо-фикстурам.

Публичный API слоя: `AIWS.db` (createLead/updateLead/deleteLead/moveLeadStage,
createDocument/updateDocument/deleteDocument, toggleOnboarding, addMessage,
resetAll/exportJSON/importJSON), `AIWS.ui` (openModal/closeModal/поля форм),
`AIWS.scriptedReply(role, text)`.

## v3: адаптив и покрытие импорта/экспорта

Закрыты два пробела, оставшихся после v2: мобильный адаптив и автотест экспорта/импорта.

- **Адаптив 375/768**: верхняя панель ужалась (`#collapseBtnTop` и trial-чип скрыты на мобильном,
  `search` получил `min-width:0`); убран корень переполнения — grid-item'ам выставлен `min-width:0`,
  поэтому внутренние `.tbl-scroll`/`.kanban` (уже с `overflow-x:auto`) реально скроллятся внутри,
  а не рвут страницу; plain `.grid` (2-кол.) стекает уже на ≤1023; на телефоне `.row` разрешает
  перенос. Таблицы и канбан горизонтально скроллятся, чарты — `svg { max-width:100% }`.
- **Автотест импорта/экспорта**: `io_check.js` гоняет полный цикл — экспорт ловится через событие
  `download`, импорт подаётся через `filechooser` (как реальный файл), проверяется roundtrip,
  выживание после reload и отказ при неверной версии. Заодно `importJSON` стал надёжнее:
  `<input type=file>` прикрепляется к DOM перед кликом (иначе некоторые браузеры не открывают диалог).

## v4: новые разделы + генерация PDF в браузере

- **Календарь** (группа «Работа»): месячная сетка с навигацией < Месяц > и «Сегодня», дни с
  событиями отмечены точками по типу (звонок/дедлайн/встреча/обучение), сегодня подсвечен;
  сбоку — ближайшие события. События персистят (`CALENDAR_EVENTS`).
- **Задачи** (группа «Работа»): список с чекбоксом (toggle done → зачёркивание), фильтр
  Все/Активные/Выполненные, KPI (всего/активно/выполнено/просрочено), создание через модалку
  (приоритет/срок/исполнитель/раздел), удаление. Полный CRUD персистит (`TASKS`).
- **Уведомления**: bell в topbar с бейджем непрочитанных → выпадающая панель; клик по строке
  отмечает прочитанным, «Прочитать все» — массово; закрывается кликом вне. Персистят (`NOTIFICATIONS`).
- **PDF документов**: кнопка «PDF» в Документах генерирует настоящий PDF (A4) счёта/КП/акта с
  шапкой, реквизитами, таблицей позиций, итогом и подписями. Реализовано на **jsPDF**; кириллица —
  через встроенный шрифт **Liberation Sans** (стандартные шрифты jsPDF кириллицу не содержат).
  jsPDF (365 КБ) и шрифт (1.1 МБ base64) грузятся **лениво** при первом клике «PDF», поэтому старт
  приложения остаётся быстрым. Без сети и сборки.

## v5: drag-and-drop задач, печать, экспорт .ics

- **Доска задач (DnD «как канбан»)**: в Задачах переключатель **Список / Доска**. Доска — 3 колонки
  по приоритетам (Высокий / Средний / Низкий); карточки перетаскиваются между колонками, и при
  drop приоритет задачи меняется и персистит (`updateTask`). Переиспользованы DnD-паттерн и
  CSS-классы канбана CRM (`.kanban-card[draggable]` + `.kanban-col[data-priority]`).
- **Печать документов (`window.print`)**: рядом с «PDF» в Документах кнопка «Печать» — альтернатива
  без встроенного шрифта. Документ (счёт/КП/акт) собирается в скрытый **iframe** с чистым
  print-CSS, вызывается `window.print()`; кириллицу рендерит сам браузер (шрифты ОС), так что
  «Сохранить как PDF» через диалог печати тоже даёт корректный русский текст. Без библиотек.
- **Экспорт календаря в `.ics`**: в Календаре кнопка «.ics» — генерирует iCalendar-файл (UTF-8) из
  всех событий (`BEGIN:VCALENDAR` + `VEVENT` на каждое: `DTSTART`/`DTEND`/`SUMMARY`/`DESCRIPTION`
  с кириллицей) и скачивает blob-ом. Импортируется в Google Calendar / Outlook / Apple Calendar.

## Регрессионные проверки без браузера (jsdom)

`npm run regress` — быстрые проверки логики (jsdom, без Chromium и без сети):

| Скрипт                 | Что проверяет |
|------------------------|---------------|
| `regress_data.js`      | валидация localStorage/импорта (битые данные не ломают запуск), удаление именно показанного лида, экранирование id (XSS) |
| `regress_docs.js`      | формат сумм, отсутствие выдуманных цен в PDF/печати, номер документа |
| `regress_render.js`    | режим диалога, палитра ⌘K, KPI, иконки, сохранение скролла/фокуса/ввода при перерисовке |
| `regress_ics.js`       | `.ics`: строгий разбор дат и длительностей, DTSTAMP в UTC, line folding, пропуск битых событий |
| `regress_buttons.js`   | аудит кнопок: у каждой есть обработчик или пометка «Скоро»; действия CRM, агентов, мастера, сертификата |
| `regress_rest.js`      | журнал событий, навигация по агентам, недоступный localStorage, доступность (aria, модалки, клавиатура), одна главная кнопка на экране, цвета статусов, единый конфиг названия, состояние ошибки раздела |
| `regress_import.js`    | импорт лидов из настоящих `.xlsx` (deflate и без сжатия) и `.csv` (UTF-8/cp1251), лимиты, zip-бомба, битые файлы, сценарий в интерфейсе |

Визуальные проверки (overflow, контраст, адаптив) по-прежнему выполняют Playwright-скрипты (`render_check`, `mobile_check`, `ics_check` и др.).

## Что в демо недоступно (помечено «Скоро»)

Кнопки без реализации не молчат: они помечены «Скоро» и по клику сообщают, что функция недоступна. Это добавление источников знаний,
подключение каналов и интеграций, конструктор цепочек, запросы снабжения, создание курсов, пересчёт аналитики,
сохранение настроек, смена тарифа, вложения в диалогах. ИИ-сотрудники, их инструкции и статус, курсы и сертификаты сохраняются в браузере (localStorage) и входят в экспорт/импорт JSON.
Состояния loading есть только у импорта файла; при сбое отрисовки раздел показывает состояние ошибки с кнопкой «Повторить».


## Импорт лидов из Excel и CSV

Раздел «Лиды и автокасания»: перетащите или выберите `.xlsx` / `.csv` (до 2 000 строк и 5 МБ, первая строка — заголовки). Разбор выполняется в браузере
модулем `importer.js` без внешних библиотек: `.xlsx` читается как ZIP (распаковка через `DecompressionStream`), CSV — UTF-8 или windows-1251,
разделитель `;`, `,` или Tab определяется автоматически. Колонки сопоставляются автоматически и вручную (имя, телефон, email, последний контакт, комментарий),
лиды создаются в выбранной воронке и канале; строки без имени и повторы пропускаются. Файл не покидает браузер. Лимиты защищают от «zip-бомб»; формат `.xls` не поддерживается.

## Название продукта

Единственный источник — `config.js` (`APP_NAME`, `APP_TAGLINE`): его используют заголовок страницы, PDF, печать, календарь `.ics`. Тест `regress_rest.js` следит, чтобы
название не появлялось в других файлах.


## Браузерные проверки (Playwright)

`npm run check:browser` (нужен `npx playwright install chromium`). Скрипты подменяют запросы Google Fonts пустыми ответами (`scripts/lib/offline_fonts.js`),
поэтому работают без интернета. Что проверяют: `render_check` (горизонтальный overflow на 1280/1440/1920 в обеих темах, зерно, палитра, скриншоты), `mobile_check` (375/768, drawer, прокрутка таблиц и канбана),
`dom_check` (структура разделов, фокус-кольцо клавиатурой), `io_check` (экспорт/импорт JSON), `pdf_check` (PDF со встроенным шрифтом), `v2_check` (CRUD, задачи, уведомления),
`ics_check` (строгий `.ics`), `contrast_check` (контраст WCAG AA на реальной отрисовке во всех разделах и обеих темах).
Примечание: в некоторых сборках headless-Chromium имя скачиваемого файла с кириллицей заменяется на `download` (проверка `pdf_check` «filename ends with .pdf»);
в обычном Chrome имя сохраняется.


## Обучение: тест и сертификат

На карточке незавершённого курса — «Пройти тест»: имя для сертификата, вопросы по одному, проходной балл 70%. При успехе курс получает статус «Завершён»,
выдаётся именной сертификат (ГГГГ-ММ-ДД, UTC) и открывается PDF. Тесты — демо-контент в `data.js` (`QUIZZES`), без выдуманных фактов о бизнесе.
