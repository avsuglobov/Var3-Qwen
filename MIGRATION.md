> **Статус (вариант C — гибрид).** Прототип (`download/`) остаётся живой спецификацией. Новое приложение — в `web/`.

> - [x] **Этап 2. Данные и «Обзор»** — готов: Zod-схемы, слой `lib/api` (адаптер localStorage, формат совместим с прототипом), TanStack Query, «Обзор» с KPI, графиком Recharts, онбордингом и журналом смены; состояния loading/empty/error/success; 66 unit- и 33 e2e-проверки.

> - [ ] Этапы 4–8 — по списку ниже.
>
> Отличия от промта, выявленные на этапе 1: у Fraunces нет кириллицы (в светлой теме русские заголовки набирает Source Serif 4); шрифты подключены через `next/font/local` с `unicode-range` (а не `next/font/google`), чтобы сборка не зависела от сети; генератор shadcn недоступен офлайн, компоненты написаны в его стиле вручную.
>
> Переименование (требование заказчика, с этапа 3): названия сотрудников пишутся с приставкой «AI-» вместо «ИИ-» (ИИ-РОП → AI-РОП, раздел «ИИ-сотрудники» → «AI-сотрудники», слоган «Платформа AI-сотрудников»). Единое правило — `web/scripts/ai-naming.mjs`; применяет его генератор сида и тест синхронности с прототипом, поэтому названия в приложении всегда с «AI-». Прототип `download/` переименован вместе с приложением и продолжает служить эталоном поведения.

Текущий проект — статический демо-прототип (чистый JS, без сборки). Промт требует Next.js (App Router), TypeScript strict, Tailwind + shadcn/ui, TanStack Query + Zustand, MSW, Recharts, dnd-kit, React Hook Form + Zod.
Этот документ — карта «что куда переезжает» и порядок работ. Тесты прототипа (`scripts/regress_*.js`) служат спецификацией поведения.

## Что куда переезжает

| Сейчас (прототип)                         | Дальше (Next.js)                                                                                  |
|-------------------------------------------|----------------------------------------------------------------------------------------------------|
| `config.js`                               | `lib/config.ts` (`APP_NAME`, `APP_TAGLINE`) — один в один                                          |
| `data.js` (демо-данные, словарь I18N)     | `lib/types.ts` (Agent, Channel, Lead, Deal, Stage, Funnel, Conversation, Message, Document, Template, ApprovalRule, KnowledgeSource, Integration, Course, Certificate), `lib/mock-data/*`, `lib/i18n/ru.ts` |
| `db.js`: валидаторы `CHECK.*`             | Zod-схемы в `lib/schemas/*` (те же правила: id `[A-Za-z0-9_-]`, допустимые значения полей, границы)  |
| `db.js`: CRUD и localStorage              | интерфейсы в `lib/api/*` + адаптеры: локальный (localStorage) и REST/MSW; хуки TanStack Query          |
| `app.js`: store, роутинг, палитра, UI     | App Router (`app/<раздел>/page.tsx`), Zustand только для UI-состояния, `next-themes`, `cmdk` для ⌘K |
| `renderView` с сохранением скролла/фокуса | не нужен: React сам сохраняет DOM и фокус; логика ключей экрана превращается в обычные компоненты   |
| `sections*.js` (HTML-строки)              | компоненты `components/{ui,crm,chat,agents,charts,theme}` и страницы разделов                       |
| `importer.js` (xlsx/csv, лимиты)          | `lib/import/*` — переносится почти без изменений (добавить типы); тесты на Vitest                   |
| `pdf.js` (счёт/КП/акт, сертификат, печать) | `lib/pdf/*`, jsPDF через динамический импорт; палитра печатных форм остаётся фиксированной          |
| ICS-экспорт (`sections3.js`)              | `lib/ics.ts` + общий валидатор из `scripts/lib/ics_validate.js` как тестовая утилита                |
| `styles.css` (токены в `:root` / `.dark`)  | `globals.css` с теми же переменными + привязка к `tailwind.config` и токенам shadcn                 |
| DnD на HTML5                              | dnd-kit: мышь, тач и клавиатура (стадию в инспекторе оставить как доступную альтернативу)           |
| Графики на SVG вручную                    | Recharts с токенами темы                                                                            |

## Что переносится как есть (логика и правила)

- Валидаторы и их границы, импорт `.xlsx`/`.csv` (лимиты 5 МБ / 2000 строк / защита от «zip-бомб»), сборка `.ics` (UTC `DTSTAMP`, folding, пропуск битых событий), формат сумм, номер документа, порог теста 70%.
- Правила интерфейса: одна главная кнопка на экране, статус не только цветом, критичный цвет не как цвет мелкого текста в тёмной теме, пометка «Скоро» для недоступного, состояние ошибки раздела.
- Контрастные токены тёмной темы (`--muted-foreground-strong`) и проверка `contrast_check` на реальной отрисовке.

## Порядок работ (как в промте, с критерием готовности)

1. Каркас: next-themes, токены обеих тем, шрифты через `next/font` с кириллицей, shadcn-компоненты, layout, ⌘K, переключатель темы. Готово, когда нет overflow на 1280/1440/1920 и нет hydration-предупреждений (`render_check`, `contrast_check` проходят).
2. Типы, Zod-схемы, слой данных `lib/api` с адаптером localStorage и тесты Vitest на схемы (перенести `regress_data`).
3. Разделы по группам: Обзор и онбординг → AI-сотрудники и мастер → Диалоги → CRM (журнал, канбан на dnd-kit, таблица) → Лиды и импорт → Документы и PDF → Календарь и задачи → Хранилище, Команда, Аналитика, Обучение, Снабжение → Интеграции, Настройки, Помощь. После каждой группы — e2e на Playwright по сценариям из `regress_*`.
4. Замена localStorage-адаптера на REST/MSW; состояния loading/error становятся настоящими (TanStack Query).
5. Финальная проверка: поиск хардкод-цветов, контраст, `prefers-reduced-motion`, a11y-аудит.

## Варианты решения

- **A. Остаться на прототипе.** Подходит, если нужен показ и сбор обратной связи. Ограничения: нет типов и компонентов, любые новые экраны дороже, интеграция с бэкендом — переписывание.
- **B. Полный перенос на Next.js.** Подходит, если проект идёт в разработку. Есть готовая спецификация (тесты) и карта соответствий выше; риски — Fraunces/кириллица в `next/font`, dnd-kit с клавиатурой, согласование схем с будущим бэкендом.
- **C. Гибрид (рекомендуется для старта).** Прототип остаётся «живой спецификацией», новое приложение строится рядом поэтапно по порядку выше; каждый этап принимается теми же сценариями.
