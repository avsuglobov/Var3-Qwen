# AI Workspace — Next.js (этапы 1–3: каркас, данные, «Обзор», «AI-сотрудники», «Диалоги», «CRM», «Лиды и импорт»)

Новое приложение строится рядом со статическим прототипом (`../download`), который служит живой спецификацией (вариант C из `../MIGRATION.md`).
Этап 1 — каркас (темы и токены, шрифты, layout, ⌘K, переключатель темы). Этап 2 — Zod-схемы, слой данных `lib/api`, TanStack Query и раздел «Обзор» (KPI, график, онбординг, журнал смены). Этап 3 идёт группами: «AI-сотрудники и мастер» — список команды (`/agents`), карточка сотрудника (`/agents/[id]`) с шестью вкладками, мастер создания, пауза/возобновление; «Диалоги» — единый inbox (`/dialogs`): список входящих, переписка с режимами «ИИ отвечает / Менеджер отвечает / ИИ в режиме чтения» (`lib/selectors/dialogs.ts`), передача диалога «Передать менеджеру»/«Вернуть ИИ», ответ менеджера переводит диалог в «ИИ в режиме чтения», панель контекста клиента, на мобильных список↔переписка; «CRM» — `/crm`: журнал смены с инспектором лида, канбан стадий на dnd-kit, таблица с фильтром и сортировкой; «Лиды и импорт» — `/leads`: импорт базы из .xlsx/.csv с сопоставлением колонок (`lib/importer`), пакетное создание лидов, шаблон CSV, сценарий реактивации. Остальные разделы пока заглушки с указанием этапа.

> **Названия сотрудников.** С этапа 3 приставка «ИИ-» заменена на «AI-» (ИИ-РОП → AI-РОП, «ИИ-сотрудники» → «AI-сотрудники», слоган «Платформа AI-сотрудников»). Правило одно для всех — `scripts/ai-naming.mjs`: его применяет и генератор сида (`gen-seed.mjs`), и тест синхронности с прототипом, поэтому названия в приложении всегда с «AI-». В самом прототипе (`download/`) приставка «ИИ-» тоже заменена на «AI-».

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
npm run build && npm start
```

## Решения, которые стоит знать

- **Токены.** Все цвета, шрифты, радиусы, тени и анимации — CSS-переменные в `styles/globals.css`. Дефолтная палитра Tailwind отключена (`--color-*: initial`), поэтому `bg-white` или `text-gray-500` просто не существуют; `check:colors` дополнительно ловит hex и `rgb()`.
- **Шрифты и кириллица.** У Fraunces нет кириллицы, поэтому в светлой теме русские заголовки набираются Source Serif 4, а латиница (название продукта) — Fraunces. Остальные семейства (Geist, Geist Mono, Inter, JetBrains Mono) имеют кириллицу. Файлы лежат в репозитории (`app/fonts`), подключены через `next/font/local` двумя подмножествами на семейство (latin и cyrillic с `unicode-range`): сборка и работа не зависят от сети.
- **Тема без мигания.** `next-themes` (класс `dark`, по умолчанию system) вставляет скрипт в `<head>`; иконка переключателя выбирается CSS-классом, а не состоянием, поэтому нет hydration-расхождений. Часы UTC показывают заглушку до монтирования.
- **Сайдбар.** Состояние свёрнутости хранится в куке `aiws-sidebar` и читается на сервере: разметка сразу правильная, без «прыжка». Zustand-стор создаётся провайдером на каждый запрос.
- **Тёмная тема.** Вторичный текст на приподнятых поверхностях использует токен `--muted-foreground-strong` (5,2:1 вместо 4,25:1); `critical` не применяется как цвет мелкого текста.
- **Данные.** Zod-схемы переносят правила валидаторов прототипа (id `[A-Za-z0-9_-]{1,40}`, допустимые значения, границы); типы выводятся из схем. Формат снимка хранилища и ключ (`aiws-db-v2`, `version: 1`) совпадают с прототипом: экспорт/импорт JSON работает между версиями. Битые записи отбрасываются, непригодная коллекция заменяется демо-данными, недоступный `localStorage` → работа в памяти.
- **Слой API.** Весь код зависит от интерфейса `Api` (`getApi()` в `lib/api/index.ts`); замена на REST/MSW — подмена адаптера. Имитация сети: `NEXT_PUBLIC_MOCK_LATENCY_MS` (по умолчанию 250 мс), для проверок — `localStorage["aiws-mock-latency"]` и `localStorage["aiws-mock-fail"]="1"` (имитация сбоя).
- **Сид из прототипа.** `lib/mock-data/seed.ts` генерируется `npm run gen:seed`; тест `schemas.test.ts` падает, если прототип изменился, а сид нет. С этапа 3 при генерации применяется переименование «ИИ-» → «AI-» (`scripts/ai-naming.mjs`): тот же хелпер используется в тесте синхронности, поэтому подстановка везде одна; прототип (`download/`) переименован вместе с приложением.
- **График.** Recharts грузится отдельным чанком (`next/dynamic`): первая загрузка «Обзора» 159 КБ вместо 272 КБ. Цвета — токены (`var(--primary)`), для скринридеров рядом лежит таблица-дублёр.
- **Раздел «AI-сотрудники» (этап 3, группа 1).** Маршруты `/agents` (список + мастер) и `/agents/[id]` (карточка с вкладками: Инструкция, Знания, Каналы, Воронка, Правила согласования, Тест). Вкладки — состояние клиента (как в прототипе); правка инструкции и пауза/возобновление — оптимистичные мутации TanStack Query с откатом при ошибке. Скриптованный демо-ответ тест-чата перенесён из прототипа в `lib/scripted-reply.ts` без изменений и честно помечен «не LLM». Обратная связь вместо тостов прототипа — строки `role="status"` / `role="alert"` рядом с действием (отдельная тост-система пока не вводится). Кнопки «Добавить источник» и «Подключить канал» отключены с пометкой «Скоро» до своих этапов.
- **Раздел «CRM» (этап 3, группа 3).** Маршрут `/crm` с тремя видами (состояние клиента, как в прототипе): «Журнал» — лента событий всех лидов воронки с инспектором выбранного лида (данные, события, стадия, действия), «Канбан» — колонки стадий воронки с перетаскиванием на `@dnd-kit/core` (PointerSensor для мыши и тача; клавиатурная альтернатива — список «Стадия» в инспекторе, как в прототипе), «Таблица» — фильтр-чипы и сортировка ID → Имя → Активность. Создание лида — модалка (пустое имя → «Новый лид», как в прототипе), удаление — с подтверждением; следующее имя `LD-NNNN` считается от максимума сида. Перемещение стадии — оптимистичная мутация с событием «Перемещён в стадию …» в ленте лида. Deep-link `/crm?lead=…&view=…`: «Открыть в CRM» из диалогов ведёт к лиду по совпадению имени контакта (как `ctxOpenCrm` прототипа), «Открыть диалог» из инспектора — в `/dialogs` (без выбора конкретного чата — выбор чата по `?conv=` появится вместе с доработкой «Диалогов»). Кнопка «Документ» отключена с пометкой «Скоро» до этапа «Документы и PDF».
- **Раздел «Лиды и автокасания» (этап 3, группа 4).** Маршрут `/leads`: карточка импорта — машина состояний прототипа (drop → loading → map → done / error). Парсер `lib/importer` повторяет `importer.js` прототипа без внешних библиотек: CSV с автоопределением разделителя, кавычками и fallback в windows-1251; .xlsx — свой ZIP-каталог + `DecompressionStream("deflate-raw")` + минимальный XML-парсер (DOMParser в Node нет) с лимитами 5 МБ / 2000 строк / 30 колонок / 20 МБ распаковки и понятными русскими ошибками. Шаг «map»: превью первых строк, автоподбор колонок по регэкспам (как `guessMapping` прототипа) с ручным переопределением, выбор воронки (агент — из воронки) и канала. Сбор строк — чистая функция `collectRows` (без имени — пропуск, повторы по «имя|телефон|email», заметка из колонок через « · »); создание — пакетное `leads.createMany` (одна запись в хранилище вместо сотен, валидация каждой записи) с событием «Импортирован из файла». Шаблон CSV — Blob с BOM и «;» (как в прототипе). Тосты заменены строками `role="status"` / `role="alert"`, как в других группах; «Открыть в CRM» — deep-link `/crm?view=table&funnel=<воронка импорта>`; KPI реактивации считает лиды с событием «Импортирован…». Подписи ролей цепочки на приподнятых поверхностях — `text-muted-foreground-strong` (AA в обеих темах).
- **Раздел «Документы и согласование» (этап 3, группа 5).** Маршрут `/docs`: шаблоны (чипы «Счёт / Коммерческое предложение / Акт», как TEMPLATES прототипа), карточка «Что ИИ делает сам» (два «Сам» и «Согласует» с лимитом счёта) и «Очередь согласования» — таблица (Документ/Тип/Клиент/Согласующий/Статус) с segmented-фильтром «Все / На согласов. / Одобрено / Отклонено» и пустым состоянием. Одобрение/отклонение — оптимистичные мутации с откатом; удаление — сразу с ролью=status «Документ удалён» (как в прототипе, без подтверждения). Создание — модалка (тип, клиент из лидов, согласующий «Менеджер продаж/Бухгалтерия/Руководитель», подсказка «Сумма не запрашивается (демо)»), номер «DOC-205» от максимума сида (DOC-204), подпись «Счёт №205» по типу. Кнопка «Документ» в инспекторе CRM включена: открывает ту же модалку с клиентом = имя лида (как `AIWS.openDocModal(lead.name)` прототипа).
- **Разделы «Календарь» и «Задачи» (этап 3, группа 6).** Маршруты `/calendar` и `/tasks` по `sections3.js` прототипа. Календарь: сетка месяца (Пн–Вс, dim-добивка, точки событий по типам: звонок — акцент, срок — критичный, встреча — статус), навигация «назад/вперёд/Сегодня» (смещение месяца в state), «Ближайшие события» (сортировка по дате+времени, первые 6, иконки типов, «дата · время · длительность · исполнитель»), экспорт **.ics** — порт `buildICS` из прототипа: строгий разбор дат (`parseStart`: 30 февраля и 25:00 → null), длительностей («45 мин», «2 ч», «1 ч 30 мин», «1,5 часа», «90» → минуты), folding по 75 октетов UTF-8 с продолжением через пробел, DTSTAMP в UTC с «Z» один на файл, «плавающие» локальные DTSTART/DTEND, срок без длительности — точка во времени (без DTEND), экранирование \;, \,, \n, пропуск некорректных событий и дублей UID (файл остаётся валидным), CRLF; файл проверяется TS-портом строгого валидатора `scripts/lib/ics_validate.js` (`lib/ics/validate.ts`) в unit и e2e (скачанный файл — валидатором прототипа). ## Требования и известные предупреждения

- **Node.js ≥ 22.12** (поле `engines`; `vitest` 5 и `vite` 8 не работают на более старых).
- **Зависимости:** `npm audit` — 0 уязвимостей (боевые и dev). Боевая находка по вложенному `postcss` закрыта переопределением (`overrides`) на исправленную версию; остальное обновлено `npm audit fix`.
- **ESLint 9.x** помечен npm как «no longer supported»: `eslint-config-next@15` поддерживает только ESLint 9, переход на ESLint 10 возможен вместе с Next 16 (отдельное решение, не в рамках этапа 3).
- **«install-scripts … not yet covered by allowScripts»** (npm ≥ 11): это уведомление о скриптах установки optional-пакетов (`fsevents` для macOS); приложение и проверки работают и без их запуска.
- **macOS и e2e:** `Control+A` в поле ввода на macOS — «в начало строки», поэтому тесты заменяют текст через `fill()`; палитра открывается и по `⌘K`, и по `Ctrl+K` (проверяются оба).
- **Несколько lockfile:** `next.config.ts` задаёт `outputFileTracingRoot`, поэтому лежащий рядом `package-lock.json` прототипа больше не путает Next.
