# AI Workspace — Next.js (этапы 1–5: каркас, данные, все 16 разделов, REST-бэкенд, финальный a11y-аудит)

Новое приложение строится рядом со статическим прототипом (`../download`), который служит живой спецификацией (вариант C из `../MIGRATION.md`).
Этап 1 — каркас (темы и токены, шрифты, layout, ⌘K, переключатель темы). Этап 2 — Zod-схемы, слой данных `lib/api`, TanStack Query и раздел «Обзор» (KPI, график, онбординг, журнал смены). Этап 3 шёл группами: «AI-сотрудники и мастер» — список команды (`/agents`), карточка сотрудника (`/agents/[id]`) с шестью вкладками, мастер создания, пауза/возобновление; «Диалоги» — единый inbox (`/dialogs`): список входящих, переписка с режимами «ИИ отвечает / Менеджер отвечает / ИИ в режиме чтения» (`lib/selectors/dialogs.ts`), передача диалога «Передать менеджеру»/«Вернуть ИИ», ответ менеджера переводит диалог в «ИИ в режиме чтения», панель контекста клиента, на мобильных список↔переписка; «CRM» — `/crm`: журнал смены с инспектором лида, канбан стадий на dnd-kit, таблица с фильтром и сортировкой; «Лиды и импорт» — `/leads`: импорт базы из .xlsx/.csv с сопоставлением колонок (`lib/importer`), пакетное создание лидов, шаблон CSV, сценарий реактивации; «Документы и согласование» (`/docs`), «Календарь и задачи» (`/calendar`, `/tasks`), «Служебные разделы» (`/storage`, `/team`, `/supply`, `/training`, `/analytics`) и финальная группа «Интеграции, Настройки, Помощь» (`/integrations`, `/settings`, `/help`). Все разделы реализованы, заглушек не осталось. Этап 4 — данные переехали с localStorage на сервер: REST-маршруты `app/api/*` поверх того же движка снимка (формат прототипа, файл `.data/db.json`), клиент ходит по HTTP через REST-адаптер (`lib/api/rest-adapter.ts`) и TanStack Query, так что loading/error — настоящие сетевые состояния; панель сбоев `/api/debug` и набор `e2e/api.check` проверяют контракт, восстановление после битого файла и переживание перезапуска. Этап 5 — финальная проверка качества: a11y-аудит axe-core (WCAG 2.0/2.1 A+AA) по всем разделам в обеих темах и на оверлеях, поведенческие проверки `prefers-reduced-motion` и сканер хардкод-цветов в `npm run check` (`e2e/a11y.check`).

> **Названия сотрудников.** С этапа 3 приставка «ИИ-» заменена на «AI-» (ИИ-РОП → AI-РОП, «ИИ-сотрудники» → «AI-сотрудники», слоган «Платформа AI-сотрудников»). Правило одно для всех — `scripts/ai-naming.mjs`: его применяет и генератор сида (`gen-seed.mjs`), и тест синхронности с прототипом, поэтому названия в приложении всегда с «AI-». В самом прототипе (`download/`) приставка «ИИ-» тоже заменена на «AI-».

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
npm run build && npm start
```

## Решения, которые стоит знать

- **Токены.** Все цвета, шрифты, радиусы, тени и анимации — CSS-переменные в `styles/globals.css`. Дефолтная палитра Tailwind отключена (`--color-*: initial`), поэтому `bg-white` или `text-gray-500` просто не существуют; `check:colors` дополнительно ловит hex и `rgb()`.
- **Шрифты и кириллица.** У Fraunces нет кириллицы, поэтому в светлой теме русские заголовки набираются Source Serif 4, а латиница (название продукта) — Fraunces. Остальные семейства (Geist, Geist Mono, Inter, JetBrains Mono) имеют кириллицу. Файлы лежат в репозитории (`app/fonts`), подключены через `next/font/local` двумя подмножествами на семейство (latin и cyrillic с `unicode-range`): сборка и работа не зависят от сети.
- **Тема без мигания.** `next-themes` (класс `dark`, по умолчанию system) вставляет скрипт в `<head>`; иконка переключателя выбирается CSS-классом, а не состоянием, поэтому нет hydration-расхождений. Часы UTC показывают заглушку до монтирования.
- **Сайдбар.** Состояние свёрнутости хранится в куке `aiws-sidebar` и читается на сервере: разметка сразу правильная, без «прыжка». Zustand-стор создаётся провайдером на каждый запрос.
- **Тёмная тема.** Вторичный текст на приподнятых поверхностях использует токен `--muted-foreground-strong` (5,2:1 вместо 4,25:1); `critical` не применяется как цвет мелкого текста.
- **Данные.** Zod-схемы переносят правила валидаторов прототипа (id `[A-Za-z0-9_-]{1,40}`, допустимые значения, границы); типы выводятся из схем. Формат снимка хранилища и ключ (`aiws-db-v2`, `version: 1`) совпадают с прототипом: экспорт/импорт JSON работает между версиями (и у прототипа, и у обоих адаптеров). Битые записи отбрасываются, непригодная коллекция заменяется демо-данными.
- **Слой API (этап 4).** Весь код зависит от интерфейса `Api` (`getApi()` в `lib/api/index.ts`). С этапа 4 `getApi()` возвращает **REST-адаптер**: fetch к `/api/*`, HTTP-коды сервера разворачиваются обратно в `ApiError` (400 validation, 404 not_found, 409 duplicate, 422 invalid_import, 503 unavailable), сетевой сбой — понятное «сервис недоступен». Состояния loading/error теперь настоящие: задержку и недоступность имитирует сервер (`/api/debug`), клиент лишь ходит по сети. Адаптер localStorage остаётся офлайн-вариантом интерфейса и спецификацией движка в unit-тестах. MSW (`msw/node`) используется в тестах REST-адаптера как подмена сети; на runtime MSW не нужен — бэкенд настоящий (маршруты Next.js).
- **REST-бэкенд (этап 4).** Маршруты `app/api/*` — тонкая обвязка над тем же движком, что и у localStorage-адаптера (`createLocalApi`): единая Zod-валидация, формат снимка прототипа, демо-фикстуры. Состояние живёт в файле `.data/db.json` (атомарная запись tmp+rename, каталог в `.gitignore`) и переживает перезапуск `next start`. Слаги коллекций: `GET/POST /api/collections/<коллекция>`, `GET/PUT/DELETE /api/collections/<коллекция>/<id>`, `POST /api/collections/leads/batch` (createMany), `POST /api/collections/courses/<id>/complete` (completeCourse), `GET/PUT /api/company-profile`, `GET /api/reference/<название>`, `GET /api/data/export`, `POST /api/data/import`, `POST /api/data/reset`. `/api/debug` — панель сбоев для e2e: `fail` → 503 на все запросы данных, `latencyMs` → задержка ответов, `corrupt` → битый файл, из которого движок восстанавливает демо-данные (тот же сценарий «повреждённого хранилища», что и в прототипе).
- **Сид из прототипа.** `lib/mock-data/seed.ts` генерируется `npm run gen:seed`; тест `schemas.test.ts` падает, если прототип изменился, а сид нет. С этапа 3 при генерации применяется переименование «ИИ-» → «AI-» (`scripts/ai-naming.mjs`): тот же хелпер используется в тесте синхронности, поэтому подстановка везде одна; прототип (`download/`) переименован вместе с приложением.
- **График.** Recharts грузится отдельным чанком (`next/dynamic`): первая загрузка «Обзора» 159 КБ вместо 272 КБ. Цвета — токены (`var(--primary)`), для скринридеров рядом лежит таблица-дублёр.

- **Финальный a11y-аудит (этап 5).** `e2e/a11y.check` гоняет axe-core (`wcag2a`, `wcag21a`, `wcag2aa`, `wcag21aa`) на 18 маршрутах в обеих темах и на трёх оверлеях; найденное правится в коде, а не отключается в правиле. Три реальных исправления: (1) `aria-hidden-focus` — Radix скрывает фон через `hideOthers` (только `aria-hidden`, без `inert`), поэтому клавиатура добиралась до скрытых элементов; `app-shell` дублирует скрытие — MutationObserver ставит `inert` на корень, когда на нём появляется `aria-hidden` (проверяется e2e на меню темы). (2) `label-content-name-mismatch` у кнопки поиска — доступное имя теперь содержит видимый текст и шорткат подряд («…лидам… Ctrl K — открыть палитру команд»; axe не исключает `aria-hidden`-kbd из видимого текста, скобки вырезает и требует неразрывной подпоследовательности токенов). (3) `nested-interactive` на «Лидах» — дропзона больше не фальшивая `role=button` с настоящей кнопкой внутри: это чистый drag-таргет (drag — мышиное взаимодействие), доступный способ выбрать файл — кнопка «Выбрать файл» (мышь и клавиатура). `prefers-reduced-motion` проверяется по поведению, а не только по CSS: под эмуляцией reduce на странице не должно остаться ни одного `animation`/`transition` дольше 1 мс, зерно скрыто, а контрольная проверка подтверждает, что без reduce переход сайдбара жив (есть что глушить). Хардкод-цвета ловит `check:colors` в `npm run check`; контраст AA по всем разделам и темам — контраст-проба в `e2e/shell`.

## Требования и известные предупреждения

- **Node.js ≥ 22.12** (поле `engines`; `vitest` 5 и `vite` 8 не работают на более старых).
- **Зависимости:** `npm audit` — 0 уязвимостей (боевые и dev). Боевая находка по вложенному `postcss` закрыта переопределением (`overrides`) на исправленную версию; остальное обновлено `npm audit fix`.
- **ESLint 9.x** помечен npm как «no longer supported»: `eslint-config-next@15` поддерживает только ESLint 9, переход на ESLint 10 возможен вместе с Next 16 (отдельное решение, не в рамках этапа 3).
- **«install-scripts … not yet covered by allowScripts»** (npm ≥ 11): это уведомление о скриптах установки optional-пакетов (`fsevents` для macOS); приложение и проверки работают и без их запуска.
- **macOS и e2e:** `Control+A` в поле ввода на macOS — «в начало строки», поэтому тесты заменяют текст через `fill()`; палитра открывается и по `⌘K`, и по `Ctrl+K` (проверяются оба).
- **Несколько lockfile:** `next.config.ts` задаёт `outputFileTracingRoot`, поэтому лежащий рядом `package-lock.json` прототипа больше не путает Next.
